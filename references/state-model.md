# Structured state and idempotency

`$JOURNAL/state.json` is the sole authority for one isolated run. `$JOURNAL/state.md` is generated by `scripts/state.js`; never edit it. Only the root orchestrator may call state mutations.

## Required rules

1. A normal URL invocation always begins with `new-run.js`; never probe the working directory for prior state. Initialize once with `node <skill>/scripts/state.js init $JOURNAL [$JOURNAL/workbook.json]` after the target/roster artifact exists.
2. Resume logic is opt-in only: the user must explicitly request it and identify the exact run path. Then run `state.js reconcile $JOURNAL`, followed by `state.js status $JOURNAL --json`. Never infer a resume from files, a matching target, or an unfinished run.
3. For workbook runs, extraction first routes to `dependencies: pending_discovery`. Run `discover-references.js`, record its hash with `state.js record-dependencies`, then resolve every expansion candidate with `state.js resolve-dependencies`. Selected targets are appended as `origin: referenced_dependency`, extracted serially, and route back to discovery. Repeat until no new candidates remain; included IDs deduplicate cycles. Declines remain recorded boundaries. Legacy runs default to `resolved_legacy` and table-only runs to `resolved_table_mode`.
4. Preparation workers write only `$JOURNAL/tables/<table-id>/prepare-result.json`. Collect a completed result with `state.js collect $JOURNAL <table-id> <result-file> <expected-revision>`.
5. Workbook runs record `primitive-families.json` with `state.js record-primitive-plan` before review; table runs mark that gate `n/a`. Approve exact brief hashes with `state.js approve journal all`. A changed brief hash revokes approval on reconcile.
6. Apply external build facts through an orchestrator-authored JSON patch and `state.js patch journal <patch.json> <expected-revision>`.
7. Every mutating call uses the current revision. A mismatch means reconcile and retry; never overwrite another transition.

The normal post-preparation phases are `primitive_planning` (Workbook only), `consolidated_review`, `build_assets`, `replay_tests`, and `data_migration_offer`.

## External mutations

The coordinator alone creates the shared Workbook, edits shared state/context, and performs final cross-table wiring. After the Workbook ID and primitive plan are frozen, bounded workers may mutate distinct table/family assets in parallel. No two workers may own the same Workflow, Dataset, or shared edge. Before create/import/publish/append:

- Reconcile existing asset IDs from state and Freckle.
- Reuse an asset whose stable migration identity matches `runId + tableId + role`.
- Record IDs and content hashes immediately after success.
- Treat an unchanged, already-recorded content hash as a no-op.
- Never append a CSV chunk whose checksum is already in the import ledger.

Replay workers start only after every approved asset is built and final wiring is complete. They write table-scoped results and run concurrently only within a safe dependency wave.

A crash between an external success and state update routes to external reconciliation—not blind creation.

## Invalidations

An extract hash change invalidates that table's digest, brief, manifest, CSV, import plan, approval, and unexecuted build plan. It does not authorize deleting or recreating live assets. Reconcile those explicitly.

Completed local artifacts are written temp → validate → atomic rename. Do not rerun `build-digest.js` over a completed or partially filled brief unless the source extract was deliberately invalidated.
